The threshold model

Many discrete traits act as if a hidden normal liability had been cut at thresholds: a disease past one cutoff, a survey answer one step up at each. Move the thresholds and the category frequencies follow. With two traits, a correlation between the liabilities becomes a contingency table, and a table can be turned back into that correlation.

How it works

Categories from a liability

The liability has SD 1, because only its position relative to the thresholds can be observed: doubling every distance changes nothing you could count. A category's frequency is the normal probability between its two thresholds, so equal steps in the mean make unequal steps in frequency once the bulk of the curve has crossed a threshold.

Correlation shows up attenuated

With two traits, each cell of the table is the bivariate normal probability of a rectangle, computed exactly. Scoring the categories 0, 1, 2, … and correlating the scores gives a smaller number than the latent ρ, more so with few or lopsided categories. The polychoric correlation (tetrachoric for 2 × 2) undoes this by fitting ρ to the table.

Fitting a table

Thresholds come from the cumulative margins (the normal quantile of each running share), then ρ maximises the multinomial likelihood of the cells with the thresholds held fixed. This is the two-step estimate that R's polycor package gives by default; its standard error treats the thresholds as known.

The cos-π shortcut

The original R scripts estimated tetrachoric correlations with cos(π / (1 + √(AD/BC))), where A, D are the concordant and B, C the discordant counts. That formula is exact only when both traits are split at their medians; with lopsided margins it is off, which is why the values here are computed from the bivariate normal instead. Scripts and agents can run the same computations through the API.
