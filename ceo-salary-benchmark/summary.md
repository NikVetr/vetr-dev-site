# CEO salary benchmark

This directory contains a validated public-record CEO compensation benchmark for Rethink Priorities and a standalone vanilla HTML/CSS/JavaScript explorer intended for `https://vetr.dev/ceo-salary-benchmark/`. The route is deliberately absent from the vetr.dev homepage project list.

## Web application

`index.html`, `style.css`, `app.js`, and generated `app-data.js` form the static GitHub Pages application. The desktop layout uses a settings column, a central weighted histogram and quantile view, and a sortable/filterable evidence table. Narrow layouts stack these regions.

The default All evidence view pools incumbent Schedule J base salary with recruitment-posting midpoint, both in July 2026 USD. Users can switch to either source stream alone, and incumbent-only users can also select validated Part VII cash/W-2 or filing-total proxies. The combined view does not pool all three filing measures because that would duplicate correlated observations from the same executive and falsely inflate precision. Evidence type remains available as a filter, table column, scatterplot color variable, and optional 50/50 stream-balancing rule.

The acquisition manifest contains 353 archived files—175 supporting web pages, 136 Form 990s (135 peer filings plus RP's filing-only reference), 34 job-ad files, 7 frozen inputs, and 1 documented search record—across 200 named organizations. Many files support peer discovery, metadata, validation, or documented exclusion; some organizations have multiple files. The default histogram instead contains the 110 validated incumbent base-salary observations plus 15 quantitative recruitment postings that pass the validated analysis preset. The RP reference remains outside every analytical sample. Alternative axes and scatterplots may contain fewer marks because rows without every selected value cannot be plotted. The archive count is documented here and in the acquisition manifest rather than displayed in the app header.

The default view is an equally weighted lognormal summary with its density overlaid on the histogram; empirical and gamma summaries are explicit alternatives. The fitted density has a white halo for contrast against colored blocks. When a fitted model and fewer than 21 quantile levels are selected, checked-by-default curve marks identify modeled percentiles and their formatted axis values with separately positioned label lines. In the empirical view, the same Mark graph control instead draws full-height dashed percentile guides behind the histogram blocks, with percentile and formatted-value labels at the top of the plot. In both modes, the percentile identifier uses RP's dark blue while the value remains neutral charcoal. Both annotation modes prioritize percentiles nearest the median and suppress any rendered label that would overlap a retained neighbor. Each fitted-model orthogonal tick retains a continuous dark stroke across the fitted curve, while only its white halo is split around the intersection. The initial 2–200 bin control sits directly below the visible axis setup and is calibrated to make organization blocks approximately square at the current viewport. The histogram always shows exact-observation rug marks, reserves headroom above the tallest mark, and labels both axes. Short horizontal-axis tick marks are omitted so they do not resemble rug observations; hovering or focusing a histogram block emphasizes its exact corresponding rug mark. A dashed RP reference guide terminates in the local RP favicon above the plot whenever RP has the displayed axis value and uses the same interactive evidence tooltip as peer marks. Tooltips identify the organization and role, present the active value prominently, and report its weighted empirical midrank percentile within the currently plotted peer sample alongside the bin or scatter coordinate, advertised range where applicable, peer tier, evidence year and type, match score, effective weight, and active color category. Sidebar controls switch between histogram and scatterplot and apply a shared color field—tier, area, EA relationship, evidence stream, job-title group, or structure—to either view. Responsive radio groups keep labels inside their controls, and viewport-based chart rows prevent browser zoom from leaving an oversized, stale chart. For color encoding, the recruitment taxonomy is consolidated into readable Tier A / primary, Tier B / secondary, and Tier C / expanded legend groups; exact source-native subtiers remain visible in the table and tooltip. Visible descriptions and collision-aware help explain the category codings, including the tier hierarchy.

The dollar-basis control switches the chart, fitted distribution, quantiles, salary filter, previews, and shareable analytical state between inflation-adjusted July 2026 USD and nominal source-year dollars. The table keeps both measures visible simultaneously: `2026 Adj. Salary` shows the adjusted analytical observation, while `Reported Salary` shows source-year Form 990 base compensation or the exact source-advertised recruitment range. Reported Salary sits immediately before Source; both salary columns sort on their corresponding scalar analytical value, with recruitment ranges sorting by midpoint. Because the chart's salary scale changes, switching basis resets the salary range to its new full extent while preserving any unrelated expense-range filter. Adjusted values follow BLS CPI-U for all urban consumers, U.S. city average, all items, not seasonally adjusted (CUUR0000SA0), targeting the July 2026 index of 333.918. Form 990 compensation uses the annual-average CPI for its IRS compensation calendar year; recruitment evidence uses posting-month CPI where available. Source previews preserve the verbatim nominal evidence text in both modes and state the active basis, CPI factor, and reference period.

The histogram horizontal axis and both scatterplot axes are independently selectable by clicking the plain in-chart label or its vertically centered blue triangle. Available measures are salary, expenses, revenue, staff, match score, and evidence year. Each visible axis has its own Measure/Ratio type control, so one scatter axis can remain a measure while the other shows a ratio; ratio mode divides independently selected positive numerators and denominators. Defaults are salary/expenses for histogram and scatter-vertical ratios and expenses/staff for scatter-horizontal ratios. Each visible axis also has a conventional two-option Linear/Log control styled like the other sidebar radio settings. Selecting a new measure or switching between Measure and Ratio activates the recommended explicit scale—log for ratios, expenses, revenue, and staff; linear for salary, match score, and evidence year—after which the user may override it. Returning to a chart view preserves any manual override unless the selected type or measure changes. The histogram omits a redundant “Horizontal axis” heading, while scatter settings retain horizontal and vertical headings. Chart labels and response-profile labels show only the underlying quantity and units; raw tick values make the active scaling evident without suggesting that the displayed values themselves were replaced by logarithms. Log histograms use equal-width intervals in log coordinates and transform fitted densities with the change-of-variable Jacobian, so block totals, fitted curves, quantile marks, ranks, rugs, RP guides, and tick labels remain on the same mathematical scale. Positive ratios remain eligible for empirical, lognormal, gamma, and covariance summaries; rows missing either operand are omitted from that plot and plotted weights are renormalized to mean one. The quantile table follows the histogram axis or scatter vertical axis, including its fitted model, values, labels, ranks, and hover guide. Tooltips report separate weighted empirical midrank percentiles for both scatter axes. When RP has both selected values, the chart adds its favicon as a white-outlined reference point and reports RP's percentile position against the plotted peers; no RP point is shown for any expression requiring the unavailable RP match score. A single comma-separated summary at the far left of the control header reports weighted Pearson and weighted rank-based Spearman correlations on the displayed axis scales to three decimals, keeping statistics outside the plotting area. Point area is linear in normalized total weight and capped at ten times the unweighted reference area. Whenever analytical or row-specific weights are active, the legend adds 0.5×, 1.0×, and 2.0× reference circles whose areas follow that mapping. The covariance-contour control sits beneath Chart view in the settings panel. Optional weighted bivariate-normal covariance ellipses show approximately 50%, 80%, and 95% data contours on the displayed scales; they are descriptive data ellipses, not causal or parameter-confidence intervals. RP may extend the displayed axes so its reference remains visible, but it is never passed into peer bins, model fits, quantiles, correlations, contours, weights, or observation counts.

Sample presets are described in place: the validated analysis set follows the source and role-structure audit; validated + sensitivity adds the four explicitly designated sensitivity-only recruitment records; the structurally clean subset additionally removes flagged structures; Tier A / strict-primary is the narrowest peer definition; and every observed salary additionally includes excluded or unresolved salary records. The Evidence stream control is independent: All evidence combines Form 990 and recruitment rows but does not override sample eligibility. Weighting is component-based: users may combine expense similarity, staff similarity, recency, tier, EA relationship, evidence stream, area, title group, and structure. Auto-weights is a visually separated, mutually exclusive alternative because its frozen 0–100 composite peer score already combines function, expenses, staff, EA affinity, executive structure, and geography; selecting it clears the individual components and prevents accidental double-counting. Its explainer sits beside the title of the unindented response panel that appears only when Auto-weights is active. The separate Equalize evidence streams rule rescales Form 990s and recruitment postings after other weights so each contributes 50% of total analytical weight; it is available only in the combined view, remains compatible with Auto-weights, and is visually distinct from row-level components. The opaque component checklist sticks at the top of the desktop settings scroller with a small white inset, fully covers earlier controls, and lets the dynamic base-weight description scroll beneath it. Active component multipliers and any user-edited row multiplier are multiplied together, after which all positive rows in the filtered analysis sample are normalized to mean weight 1. Automatic table weight cells update with that normalized total; explicitly edited cells remain visibly marked and retain their user multiplier. Every discrete component opens with documented suggested category values: 1.00 is the reference, lower values moderately downweight broader tiers, weaker EA or topical fit, advertised rather than realized compensation, less directly comparable titles, and structurally dissimilar organizations. Every category row has a keyboard-accessible, collision-aware explainer grounded in the frozen non-pay protocol: tier explainers state the score, function, scale, role, and structural rules; EA explainers distinguish explicit EA-core, EA-adjacent/recommended-cause, functional-only, and uncoded relationships; structure explainers decode the source-derived legal, governance, and reporting arrangements. Uncoded categories remain neutral where penalizing missing metadata would be misleading. Suggested values are initialized on first activation, remain directly editable when a component is toggled off and on, and return to their defaults only with the global reset. Each continuous component's compact response curve follows that component's own target/bandwidth or half-life controls, so adjustments and their implications remain visually grouped. Every response plot has four ticks per axis and explicit variable and multiplier labels. Expense and staff plots include directly labeled RP reference lines at the $7.5M core budget and 57-FTE operating target; if the user changes a weighting target, the fixed RP marker remains visible separately. Organization-specific multipliers and row inclusion toggles remain available. Rows without the active compensation measure are consistently excluded from both the chart and table. Each chart mark focuses the corresponding evidence row.

The RP size defaults are source-backed rather than guessed. Expense similarity targets RP's published $7.5 million 2026 core budget, which excludes the expenses of fiscally sponsored Special Projects. Staff similarity uses RP's published operating scale of 57 full-time equivalents from its archived funding-needs page. Because that FTE figure is not identical to Form 990 Part I, line 5, the app labels it as a weighting target and keeps the filing-comparable table field separate. A dark-blue Rethink Priorities reference row is always the first table row and remains frozen directly below the sticky header while the evidence scrolls. It uses RP's 2024 Form 990 (`benchmark/sources/native/form990/202502879349301540_public.xml`) for Marcus Davis's compensation, $20,378,936 total functional expenses, and $20,599,841 revenue, and RP's complete public 2023 filing for the most recent usable filing-comparable staff count of 43; the 2024 filing reports zero in that field. Both filings and the operating-headcount page have cached originals. Compensation follows the app's inflation-adjusted/source-year toggle. The row has no inclusion checkbox or analytical weight, opens the same source-evidence dialog used by peer filings, and presents its filing links compactly as sources 1 and 2. The same frozen row supplies the display-only RP marks and their tooltips in both chart modes. These marks use the transparent RP favicon with a thin contour-following white halo rather than a rectangular backing, and remain excluded from distributions, fits, correlations, and contours. The page favicon is a local copy of the icon declared by the official RP website.

Organization and source-native job-title fields are separate. The title filter groups exact, indented source titles beneath CEO, Executive Director, President, Co-leadership, Other, and Not-reported family checkboxes rather than replacing their displayed wording. A family checkbox is checked only when all of its exact titles are checked, shows a partial state otherwise, and selects or deselects only its own children. The Area filter applies the same nested interaction to ten broad navigation families while retaining exact analytical area values as children. The data build rejects scale metadata such as budget, staff, revenue, or expenses if it appears in the normalized recruitment Area field; source-native wording remains available separately in evidence previews. The Job title column is deliberately compact and wraps long source-native titles instead of truncating them, while Staff sits directly after Expenses. A filter whose values are all checked offers “Deselect all”; partial or empty selections offer “Select all.” Evidence type, title, tier, area, location, EA relationship, and organizational-structure columns use exact-value checkbox menus that support multi-selection. Only one column-filter popover can be open at once, and an open popover closes automatically once horizontal scrolling moves its column outside the table viewport. Evidence is followed by Reported Salary and the final Source column, whose Preview button and external Open link share one cell. All filter affordances are icon-sized funnels positioned immediately to the right of their sortable labels in the table's single header row: inactive funnels are neutral, active funnels are blue, and the expanded menu reports the selected count or active range. Salary, Expenses, and Match score reveal two-ended range controls only while their popovers are open; the expense control uses a logarithmic scale and match score uses its documented 0–100 scale. Categorical and numeric filters update the table, chart, fitted distribution, statistics, and quantiles from the same observation subset. The global table search and invariant work-model column are omitted. The table initially sorts from the narrowest peer tier to broader, sensitivity, and excluded tiers, with organization name as a stable secondary key. Every sortable column shows a persistent sort affordance and exposes its active direction accessibly, while the compact Tier column truncates long labels with their full value available on hover. Unchecked rows with usable salary evidence expose their frozen non-pay exclusion reason on the checkbox tooltip and remain manually includable; rows without a usable salary measure explain that separate limitation and cannot be included. Dotted missing-metadata cells explain on hover why EA relationship or structure was left uncoded rather than presenting absence of evidence as a substantive classification.

The table also exposes staff count and evidence year. Preserved Form 990 website declarations supply organization-homepage links for 121 incumbent peers. Hovering or focusing the organization-name text—not unused space elsewhere in its cell—opens a concise Wikipedia card without repeating table metadata. `data/organization_wikipedia_profiles.csv` records a complete 174-organization audit: 98 mappings use an exact organization title/redirect or a manually reviewed override, while 76 ambiguous or absent articles remain intentionally unmapped. The runtime requests only the mapped article title, never the first search result; unmapped organizations show a neutral unavailable message and a search link. `scripts/audit_wikipedia_profiles.py` can refresh the mapping conservatively, and the app-data build fails on incomplete coverage or an unapproved mapping method. Quantiles can be shown as quintiles, deciles, all percentiles, or user-entered percentile levels, and the panel identifies whether they come from empirical weighted ranks or a fitted distribution. Ordinal suffixes in percentile labels are superscripted. Hovering or focusing a quantile projects it onto the chart. The interface uses the Rethink Priorities blue palette and the local Aspekta variable font. Help tooltips use collision-aware fixed positioning so they remain inside the viewport. Scrollable panels reserve a stable internal gutter and use narrow, semi-transparent scroll thumbs, preventing scrollbar appearance from shifting panel contents.

Quantile-relevant analysis state is shareable through one versioned, compact, base64url query parameter. The fifth schema makes All evidence, inflation-adjusted dollars, Measure mode, and the default axis expressions omitted defaults while retaining short field codes and stable hashed row identifiers for the dollar basis, model, evidence/measure/sample choices, the active histogram or scatter-vertical quantile variable, ratio operands, active weights and nondefault parameters, edited row multipliers, inclusion overrides, analytical filters, numeric ranges, and requested quantile levels. Scatter view is retained only when it activates a nondefault vertical quantile mode or expression. Scale overrides, the scatter-horizontal mode and expression, bins, color, contour visibility, graph-mark visibility, and table sorting remain deliberately excluded because they do not determine the quantile output. Legacy version-one through version-four links remain readable; version-four's former shared ratio mode is applied to all three axes when such a link is restored. The page restores links without network storage, uses `history.replaceState` as settings change, removes state when analysis settings are at their defaults, and visibly falls back to defaults if a malformed or unsupported link is opened.

Source previews display the exact evidence fields used for the selected measure. Third-party links open the public host, while `evidence/original/` contains compactly published copies of the original XML, HTML, or PDF artifacts referenced by app observations, including CSCCE's supplemental official About-page PDF. `scripts/build_app_data.py` rebuilds both the app dataset and this publishable source subset from the validated benchmark deliverables.

The preserved category-explainer package under `benchmark/deliverables/category_explainers/` contributes the frozen historical taxonomy and 312 row-level provenance records: 144 selected-reference classifications, 135 Form 990 observation classifications, and 33 job-ad classifications. A separate, explicitly post-freeze enrichment under `benchmark/enrichment/` codes all 33 recruitment postings for EA relationship, organization structure, and a compact eight-category area taxonomy while retaining the historical record alongside it. `job_ad_evidence_updates.csv` is a still-separate evidence-review overlay for changes justified by newly archived source-native material. It currently promotes Seattle Botanic Gardens from historical exclusion to an `expanded_broad_functional` sensitivity observation after the saved posting verified the organization-wide role, $250,000–$290,000 salary range, publication date, and merged public-agency/nonprofit structure. CSCCE remains excluded because its newly archived official About-page PDF verifies fiscal sponsorship but not the salary posting. The enrichment records row-specific rationales and citations and distinguishes source-native mission and reporting-line text from analytical categories. All job-ad rows are complete after enrichment; the app treats their common `functional-only` EA value as a benchmarking relationship rather than a claim that no informal connection exists. The combined dictionary now contains 283 exact-value definitions. The data build fails on incomplete 33-row coverage, invalid update fields, missing update archives, missing required fields, invalid local citation paths, malformed area values, or absent historical provenance, then embeds the historical, enrichment, and evidence-update layers into `app-data.js` and publishes their methodology and data links. Discrete-weight help uses these definitions while explicitly identifying the app's suggested multipliers as editable sensitivity judgments rather than source rules. Source previews expose classification timing, provenance type, confidence, caveats, row-level rationales, and local citations. Incumbent rows retain the selected-reference taxonomy used by table filters and charts while separately showing later filing-review classifications; this preserves documented differences such as Social Science Research Council being Tier A in the selected reference set and Tier B in the filing-analysis record rather than silently overwriting either layer. Later descriptive structure flags and non-preregistered expanded job-ad subtype names are labeled as such.

## Analytical package

`benchmark/` contains the protocol chain, frozen peer universes, original analysis, independent validation, source manifests, and acquisition utilities. Stable source IDs connect analytical rows to source-native files and retrieval metadata. All 353 manifest records are locally preserved: 136 IRS XML returns, 34 job-ad records, 175 supporting web sources, seven frozen inputs, and one documented search record.

Independent parsing found that the original analysis omitted Schedule J base compensation and misstated the Center for AI Safety Part VII amounts. The app therefore uses `validated_form990_compensation.csv` and `validated_job_ad_compensation.csv`, followed by the explicit Seattle evidence-update overlay, not the uncorrected original evidence columns. All 15 default recruitment observations and all four sensitivity-only observations now have locally verified ranges. The Marine Science Institute exclusion remains unchanged, but its recovered source corrects the role title to Executive Director.

The strict `source_complete` packager remains fail-closed because it requires the original expected fields to agree with every source as well as requiring all files to exist. Its remaining failures are extraction/data-contract findings, not remote-retrieval gaps.

## Reproduction and testing

- `python3 scripts/build_app_data.py` rebuilds the static app data and publishable evidence files.
- `npm run serve` serves the route locally on port 4173.
- `npm test` starts a local server and runs focused Playwright checks for outlined histogram density, collision-decluttered fitted-curve quantile marks, full-height empirical quantile guides layered behind histogram blocks, linked block/rug highlighting, display-only RP histogram/scatter markers without a redundant legend item, chart-tooltip weighted percentiles, CPI-adjusted and nominal analysis switching, simultaneous adjusted/reported table salaries, source-native recruitment ranges, Seattle's verified sensitivity inclusion, CSCCE's retained exclusion and archived structure citation, the sticky RP reference row, shared categorical coloring, distribution switching, the combined evidence stream, complete 33-row recruitment enrichment and exact category-definition coverage, clickable unadorned histogram and scatter axes, independent per-axis Measure/Ratio modes, explicit Linear/Log defaults and overrides, log-histogram fits and quantiles, scatter colors/covariance contours/correlations/weight-scaled areas, normalized automatic and user-edited weighting, mutually exclusive composite weighting, 50/50 stream balancing, compact URL-state round trips and legacy-link recovery, weight-response curves, sample descriptions, nested title and Area family filtering, synchronized partial checkbox states, mutually exclusive and offscreen-closing filter popovers, select-all/deselect-all state, compact one-row header filters and their active states, y-axis headroom, row inclusion, salary-availability exclusion, filter-to-chart synchronization, two-ended numeric filters, percentile provenance, verified and intentionally unmapped organization previews, H-CAP and Center for AI Safety corrections, viewport-safe tooltips, evidence-stream switching, sticky overlays, zoom-sized charts, and responsive layout.
- The benchmark's independent audits and source validators remain under `benchmark/scripts/`.

The app is decision support for board deliberation, not a population salary estimator or a substitute for a formal compensation-reasonableness process.
