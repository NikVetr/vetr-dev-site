# MotRPAC Alphabet Editor

This project is a small static web application for designing alphabet letters from the geometric pieces of the MotRPAC M logo. It uses the SVG outline in `assets/motrpac-M.svg` as the source of truth for the reusable shapes: four lollipop paths, one stemless circle path, a derived no-head double-stem primitive, a curved constant-width double-stem primitive, and a head-anchored curved lollipop primitive.

The application is implemented with vanilla HTML, CSS, and JavaScript:

- `index.html` defines the editor shell, including top file/edit/shape menus, global variant controls, symbol-based header align/distribute/import/export/copy actions, the central SVG workspace, the right-side inspector, the A-Z letter strip, and the SVG favicon link.
- `styles.css` defines the responsive editor layout, stable tool controls, visible canvas grid, red centroid alignment guides, glow-based shape selection styling, two-stage polish controls, and horizontally scrollable preview thumbnail strip.
- `app.js` owns the drawing model, mouse and keyboard interactions, plain wheel panning, Control-wheel zooming, Command-wheel shape rotation, Shift-wheel color cycling, snap-to-grid translation, snap-angle rotation around each shape anchor, focused-shape combo handles, per-letter variants, deterministic two-stage polish operations, undo/redo history with selection preservation, shape copy/paste, reset, localStorage persistence, JSON import/export, and SVG export.

Each letter has one or more independent variants, and each variant contains a list of shape instances. The default alphabet is seeded from an explicit A-Z registry based on the hand-sketched reference in `assets/motrpac-letters_examples.jpeg`; A and Z variant 1 use refined five-shape coordinate configurations, M keeps the original logo layout, and W uses that M layout rotated 180 degrees. The favicon in `assets/favicon.svg` is a compact A/Z mark generated from those same default A and Z shape paths. Seeded lollipop stems are directed toward named target nodes with the original M concave-gap spacing, and seed construction fails loudly if a variant would create exact duplicate head centers. The first three variants are available from the thumbnail strip and from the global header selector, including blank variants beyond the default set, and variants can be reordered by dragging their numbered buttons. Shift-clicking a shape toggles it in or out of the current multi-shape selection. Header layout tools operate on selected anchors through symbol-only buttons: six align icons move selected shapes to min/mean/max anchor coordinates on X or Y, while two distribute icons space three or more selected anchors evenly along X or Y between the current extrema. Lollipops and circles use their head centers as anchors; no-head double-stem shapes use their stem midpoints. A shape instance records its template id, fill style id, translation, rotation angle, lollipop/double-stem length offset, curved-stem start/end bend offsets, curved-stem start/end axial control pulls, and remembered circle stem seed angle. The stored translation is anchored to the center of the lollipop head, circle, or double-stem midpoint so snapping and rotation are based on the meaningful visual pivot. During translation, the editor draws temporary guides when moved anchors align with stationary anchors along 15-degree increment lines; each guide is colored to match the stationary aligned-to shape and is rendered as repeated upright degree labels on a transparent, non-interactive canvas overlay rather than as DOM text, SVG text, or a stroked baseline. Canvas guide projection uses the SVG screen transform so guide labels lie on the same projected line as the corresponding anchors, including when the SVG is letterboxed. Guide labels are fixed at 15 CSS pixels, have no filter/stroke/background effects, and the guide overlay ignores pointer events so guides cannot intercept shape dragging. Grid lines also opt out of pointer events so the artboard or shapes receive empty-canvas drags. Lollipop stem editing regenerates the SVG path by moving the concave stem-end arc along the original stem axis while leaving the head circle fixed; stem offsets can shorten below the original logo length until the concave arc reaches the head circle boundary. No-head double-stem shapes are filled paths with concave ends on both sides and midpoint anchoring; they can be added from the menus or inspector, and double-clicking an existing shape toggles it into or out of the straight double-stem form. Straight double stems expose two square combo handles, one for each concave end; dragging either end pins the opposite end in world space, while Shift-dragging locks the current axis and only extends or contracts the active end. Curved double stems use a sampled constant-width filled outline around a cubic centerline with independent start-side and end-side bend offsets and axial control pulls, concave circular end arcs matched to endpoint tangents, the same two endpoint handles as straight double stems, two freely draggable curve handles for reshaping each side of the bend in two dimensions, outer and inner paired diamond handles that move both curve controls together while preserving their spacing, and a floating outer-surface `--[]--` rotation handle that follows the local curve tangent and changes only the overall shape angle. Circle and lollipop forms expose one square combo handle. Normal combo-handle drags rotate around the anchor and change stem length together; holding Shift at drag start or pressing Shift during an active combo-handle drag locks the current stem axis and only extends or contracts the stem until Shift is released. Stem drags show a self-colored guide when the stem is near a standard 15-degree angle and target-colored guides when the actual forward stem ray intersects another anchor. Stem guide labels display counterclockwise polar-style angles even though the SVG geometry uses screen coordinates. Circles show a thin stem seed arc as an affordance, lollipops collapse back to the clean circle template at the geometric circle boundary, and collapsed circles keep the handle on the former stem side.

Polish controls make deterministic iterative edits to the active variant, with the sidebar step count controlling how many polish passes run per click. When no shapes are selected, polish can modify the full active variant; when one or more shapes are selected, only those selected shapes are moved, rotated, lengthened, bent, recolored, or overlap-separated, while unselected shapes can still act as fixed targets. Stage 1 focuses on core logo relationships: position polish nudges lollipop/double-stem endpoint target pairs toward the original logo's concave-end displacement, angle polish locks the non-self anchor nearest to each concave stem end at the start of the click and rotates lollipops and straight double stems by their anchor-to-target axis without a final angle-grid snap, length polish locks those same nearest endpoint targets and adjusts lollipop or double-stem length offsets toward a consistent original-logo concave-arc-center-to-anchor gap without a final stem-grid snap, and overlap separation keeps head centroids at least one original head diameter plus a small margin apart, including exact coincident-centroid cases. Curved double stems have a separate Curve polish button that adjusts the start and end bend offsets against actual endpoint tangents, so overall rotation remains the responsibility of Angles and shape deformation remains the responsibility of Curve. Size polish is intentionally separate from All: it is a one-shot isometric scale of shape anchor positions around their current anchor center so the active source set's centroid Y range matches the original M centroid Y range, preserving head diameter, stem thickness, angles, stem lengths, curve offsets, and the relative ordering of centroids. All polish runs the shared length, position, overlap, angle, curve, and color passes, and finishes with a fresh angle/curve alignment pass using the current geometry, but it does not run Size because scaling centroid spacing without scaling the heads can make compact letters collapse. Double-stem polish uses both concave arc centers, not just a single visible end midpoint, so straight and curved double stems can balance both ends against separate nearby heads and stop short of target heads instead of projecting into them. Double-stem length polish uses a bounded local search over the shared length offset because one offset controls both endpoints, and curved endpoint distances also depend on bend. Stage 2 uses the same locked stem-end targets for angle and length polish, then translates connected anchors toward the shortened stem's original-logo gap instead of leaving targets behind. Color polish assigns the five logo colors to minimize reuse and avoid matching colors across stem-to-anchor adjacencies.

The editor stores work automatically in browser localStorage under `motrpac-alphabet-editor-v4`, while migrating older v1/v2 saved states when present. The older v3 key is intentionally not migrated so rejected provisional generated defaults do not override the current explicit seed registry. Exported JSON contains the complete coordinate configuration for all letters and variants, and the header copy action writes the currently viewed letter/variant JSON to the clipboard. Exported SVG files preserve the generated path data and instance transforms so the designed letters can be reused in other graphics or font-building workflows.

File → Export Font opens a live type sample and downloads an installable `.ttf` with either COLR/CPAL logo colours or monochrome outlines. `app.js` samples the existing SVG paths adaptively and applies the same shape transforms as the canvas. `font-export.js` accepts these solid contours without a DOM, validates them, and writes the OpenType tables, checksums, metrics, glyph outlines and colour layers. All selected variants share a common scale and baseline; lowercase maps to the uppercase designs and blank variants are explicitly omitted. Colour fonts retain ordinary outlines for consumers without colour support. The file contains the finished filled shapes, without the editor’s thin stroke. `window.MotRPACAlphabet.exportFont()` shares this implementation with the UI; its output and contour-level interface are documented in `api.md`. The export dialog uses `font-export.css` and keeps editor shortcuts inactive while open so typing and native text Undo remain available.

A shared two-position MotRPAC/Mattlab control sits at the start of each editor’s native header. It reuses the collection’s lightswitch and navigates between independent saved projects. The Mattlab painter remaps the hovered artwork or palette row on right-click, skipping occupied families and preserving shade columns and history. Paint cycles through three shades and a transparent blank; Erase reveals the separately selected background, with automatic outline contrast. A shared corner-owner map in its geometry module keeps tiny tips linked to the ending legs. The gallery dropdown defaults to Logo designs (NV-1/NV-2 and the warm Original scheme), with separate choices for the supplied edited ASCII and letter/digit sheets; existing edited studies survive starter updates. Background colors carry through thumbnails, opaque SVG/PNG exports and character sheets.

The shared editor switch uses identical dimensions and header coordinates on both pages, including narrow and short screens. Mattlab uses a full-width, viewport-height desktop workspace with independently scrolling palette/gallery panels and a flexible painting canvas; narrow screens retain the stacked, scrolling layout.
